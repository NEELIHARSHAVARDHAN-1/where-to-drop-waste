02

The Problem

  • Confusion at the bin — People don't know which category an item belongs to. Is a greasy pizza box recyclable? Is broken glass hazardous?
  • No location context — Recycling rules differ across India's 36 states and UTs. Generic global guidance doesn't apply locally.
  • No visual identification — Text search requires knowing what the item is. Camera-based identification makes waste sorting instant and effortless.
  • Low motivation — Without visible feedback and rewards, sustainable habits don't stick. People need to see their environmental impact.
  • AI systems don't improve — When a model misidentifies an item, that error is lost. There's no mechanism to collect feedback and improve the model over time.
Our Goal

Build a system that instantly classifies waste items from a camera photo, maps them to the right disposal category, applies location-specific rules for India, rewards eco-friendly behaviour, and continuously collects training data to improve the AI model over time.

The Solution

📸
Camera AI Classification
Photograph any waste item. Real TFLite model (MobileNetV2 / Teachable Machine) classifies it with softmax confidence scoring.
📍
Location-Aware Rules
All 28 states + 8 UTs of India with city-level recycling rules. Auto-detect via GPS or pick from hierarchical dropdown.
🏆
Gamified Experience
Points, levels, badges, streaks, leaderboard, and community challenges keep users engaged and consistently motivated.
🔄
Training Data Pipeline
Unknown items → user correction → admin review → approved dataset → offline Teachable Machine retraining. Production model never auto-retrained.
🌱
Environmental Impact
Tracks CO₂ saved, water conserved, and energy recovered per classification. Cumulative dashboard with charts.
🔐
Secure & Private
JWT auth, bcrypt (salt=12), rate limiting, input validation. GPS coords used only for reverse geocoding — never stored.

Training Data Pipeline

Unknown / Low ConfidenceTF confidence below 70% threshold
"Object Not Recognized"Model cannot classify the item at all
↓
User Correction — POST /api/classify/correctUser provides: corrected_class, corrected_category  ·  Stored with: image_path, predicted_class, predicted_confidence, user_id, timestamp
↓
training_candidates table (SQLite)status: pending | admin_approved | rejected  ·  Full metadata preserved for dataset use
↓
Admin Review — GET /api/admin/training-candidatesAdmin views image, predicted label, corrected label → POST /api/admin/training-candidates/:id/review → Approve or Reject
↓
Approved Dataset — GET /api/admin/approved-datasetManifest of approved images + correct labels for offline Teachable Machine retraining
↓
Offline Retraining (teachablemachine.withgoogle.com)Export new TFLite → Replace model_unquant.tflite + labels.txt in backend/models/teachable_machine/ → Restart backend
⚠️ The production model is NEVER retrained automatically during a user request. This pipeline is for controlled, human-reviewed dataset collection only.
